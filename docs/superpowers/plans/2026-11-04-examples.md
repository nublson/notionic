# Examples Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an Examples section to the notionic.dev docs: about ten Notion pages that show each supported block rendered live by notionic's built-in components, each with a type-checked customization recipe.

**Architecture:** The site needs four small changes:
- an Examples section in the sidebar order;
- `examplesComponents`, which keeps the site's highlighting only for code captioned `Customize…`;
- `embeds={["codepen.io"]}` on docs pages;
- a development-only switch that lists unpublished docs, so the pages can be checked before they go live.

Everything else is content: Notion pages in the docs database, written through the Notion tools.

**Tech Stack:** Next.js (apps/web), notionic, Vitest (`apps/web/lib/*.test.ts`, node environment, no TSX tests), Biome, the Notion MCP tools (`notion-update-data-source`, `notion-create-pages`, `notion-update-page`).

**Spec:** `docs/superpowers/specs/2026-11-04-examples-design.md`

## Global Constraints

- Section option name: `Examples`. Sidebar order: Getting started, Guides, Examples, Reference, Registry.
- Recipe marker: a code block whose caption's plain text starts with `Customize` (for example `Customize · callout.tsx`).
- Docs in other sections render exactly as today, with `notionComponents`.
- `embeds={["codepen.io"]}` on every docs page.
- Page slugs: `examples-text`, `examples-headings`, `examples-lists`, `examples-callouts`, `examples-code`, `examples-layout`, `examples-media`, `examples-links`, `examples-footnotes-resources`. Section `Examples`, Order 1–9 in that order.
- Each block on a page has, in order: an **In Notion** line, the live block, a **Renders as** line linking to Supported blocks, and a **Customize** code block (language `tsx`, caption `Customize · <file>.tsx`).
- Every recipe passes `pnpm --filter web typecheck` in a scratch file before it goes into Notion. The scratch file is deleted, never committed.
- Pages are created **unpublished**, and published together only in Task 5.
- Notion pages are written in Notion-flavored Markdown. Read `notion://docs/notion-flavored-markdown-spec` before the first page.

## Review Focus

- A block that Notion-flavored Markdown can't create (for example link preview, link to page, audio): the page must not claim a live example it doesn't have. Each content task handles it with a ruling: a note in place of the block, and the block named to the user to add by hand.
- An unpublished page must stay off production. `NOTION_DOCS_DRAFTS` only takes effect outside production. Pinned by the Task 1 test `ignores the drafts flag in production`.
- A recipe that compiles but misuses the API, for example forgetting `children` in a block override, so nested content disappears. Each recipe passes `children` through when the block can have any.
- The Headings page's example headings crowd its outline. Accepted by the spec; check it reads acceptably in Task 5's browser pass.
- An Examples page that renders a block as nothing: Task 5's browser pass checks every block on every page.

### Task 1: Site support for Examples

**Files:**
- Create: `apps/web/lib/examples.ts`, `apps/web/lib/examples.test.ts`
- Modify: `apps/web/lib/notion-components.ts` (add `ExampleCode`, `examplesComponents`), `apps/web/lib/docs.ts` (`SECTIONS`, drafts switch), `apps/web/app/docs/[slug]/page.tsx` (components by section, `embeds`), `docs/superpowers/specs/2026-11-04-examples-design.md` (one line on the drafts switch)

**Interfaces:**
- Produces, in `lib/examples.ts`, which is pure and has no server-only imports:
  - `export const EXAMPLES_SECTION = "Examples"`
  - `export function isRecipe(block: BlockOf<"code">): boolean`: true when the caption's plain text, trimmed, starts with `Customize`.
  - `export function includeDrafts(env: { NODE_ENV?: string; NOTION_DOCS_DRAFTS?: string }): boolean`: true only when `NOTION_DOCS_DRAFTS === "1"` and `NODE_ENV !== "production"`.
- Produces, in `notion-components.ts`:
  - `ExampleCode(props: BlockProps<"code">)`: `NotionCode` when `isRecipe(block)`, else `defaultComponents.code`.
  - `export const examplesComponents: BlockComponents = { code: ExampleCode }`

- [ ] **Step 2: Write the recipes** for these pages in `apps/web/app/_recipes.tsx`, one exported component or `components` object per recipe:

  - **Callouts:** a `callout` override using shadcn's `Alert`, or the registry's `NotionCallout`, as a `components` entry.
  - **Toggle:** the registry `NotionToggle` as `components.toggle`.
  - **Quote, divider:** a `quote` override with a colored border, and a `divider` override.

### Task 3: Code and math, Tables and layout, Media

Same steps as Task 2, Orders 5–7. Recipes:
- **Code:** the registry's `withMermaid(NotionCode)` as `components.code`, and a minimal `code` override that adds a copy button slot around the built-in `Code`.
- **Equation:** the registry's `NotionEquation` and `NotionInlineEquation`.
- **Table:** the registry's `NotionTable`. **Columns:** a `column_list` override that stacks columns below `md`. **Tabs:** the registry's `NotionTabs`. **Synced block:** none needed; the line says it renders its content.
- **Image:** `transformFileUrl` pointing at a re-signing route, plus an `image` override using `next/image` for external URLs.
- **Video, audio, file, PDF:** `transformFileUrl` only, and one `file` override showing a download button.

Media uses external URLs: the test page's Unsplash image, YouTube video and W3C PDF.

### Task 4: Links and embeds, Footnotes and Resources

Same steps as Task 2, Orders 8–9. Recipes:
- **Bookmark, link preview:** `fetchBlocks(notion, id, { bookmarkPreviews: false })` for cards without previews, and a `bookmark` override.
- **Embed:** the `demos` prop with one demo, and `embeds={["codepen.io"]}`, with a live CodePen embed URL (`https://codepen.io/<user>/embed/<id>`) in the page.
- **Child page, link to page:** `pageHref` mapping page ids to site paths.
- **Footnotes:** the `footnotes` option with `showTitle` and `title`. **Resources:** `components.resources` with a custom row.

The Footnotes and Resources page has one footnotes section and one resources section. The footnotes section comes last on the page. The resources section comes before it, under its own heading.
